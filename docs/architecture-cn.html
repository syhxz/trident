2. 核心组件

组件职责关键接口
ConnectionHandler单客户端会话全生命周期：Startup → 消息循环 → 清理；查询期间移动并独占一个完整后端连接handle()
Router串联 Hint → 事务状态 → SQL分类 → Cost → 一致性检查 → 负载均衡route(sql, ctx, readers, analytics)
PoolManager按节点管理连接池；idle、Session binding 和 pinned 队列直接拥有完整连接pool_for(node_id), snapshot()
BackendConnection物理连接所有权单元：metadata + socket + node generation + application_name 缓存conn.stream, conn.generation
ConnectionRegistry仅跟踪动态节点 generation；不保存 socket，也不参与查询热路径generation_for(node_id)
HealthChecker周期性并发探活，连续3次规则触发状态翻转check_once(), run()
LsnTrackerSession 级 + Global 级 WAL 水位单调维护record_write(), session_write_lsn()
Forwarder通过 &mut conn.stream 流式转发消息，执行 Pipeline LSN 获取和 Extension GUC 捕获forward_simple_query_with_options()
CancelRegistryCANCEL 请求的 key→session→backend 映射；与连接所有权 registry 独立resolve_cancel_target()

后端连接所有权与查询热路径

flowchart LR H["ConnectionHandler"] -->|"acquire()"| P["NodePool
idle / session / pinned"] P -->|"move out"| C["BackendConnection
metadata + socket + generation
application_name cache"] C -->|"&mut conn.stream"| IO["PG Wire 直接转发"] IO -->|"release(conn)"| P C -->|"discard / drain / drop"| Close["关闭自有 socket"] G["ConnectionRegistry
仅 node generation"] -.->|"动态节点替换"| P

连接池 checkout 返回完整的 BackendConnection，Handler 直接在其 socket 上读写，再把同一个对象移回连接池；不再按 (node_id, backend_pid) 执行 ConnectionRegistry::take/insert。Transaction 模式的 idle 队列、Session binding 和 pinned 队列都保存完整连接，Session checkout 使用 move-out/move-back，不复制连接。

生命周期保证：draining pool 会拒绝新 checkout、唤醒 waiter，并丢弃随后归还或刚创建完成的连接。清理成功后会清空 application_name 缓存；设置新标签失败时查询不会继续执行。连接或 pool 被 drop 时，其拥有的 socket 自动关闭。

4. LSN 跟踪模式

4.1 Pipeline 模式

双 Query Frame — 零额外网络往返

sequenceDiagram participant C as Client participant T as Trident participant B as Backend (Writer) C->>T: Query("INSERT INTO t VALUES (1)") Note over T: 检测到自提交写语句
pipeline_safe_sql = true T->>B: [TCP write_all]
Query Frame 1: INSERT INTO t VALUES (1)
Query Frame 2: SELECT pg_current_wal_lsn() Note over B: 处理 Frame 1
执行 INSERT (autocommit) B->>T: CommandComplete("INSERT 0 1") T->>C: CommandComplete("INSERT 0 1") B->>T: ReadyForQuery(Idle) Note over T: 暂存 RFQ，不转发 Note over B: 处理 Frame 2
此时 INSERT 已提交 B->>T: DataRow("16/B374D848") B->>T: CommandComplete("SELECT 1") B->>T: ReadyForQuery(Idle) Note over T: 解析 LSN = 0x16B374D848
record_write(session, lsn)
吞掉内部响应 T->>C: ReadyForQuery(Idle) Note over C: 收到完整正常响应
不感知内部 LSN 查询

Pipeline COMMIT 路径（显式事务）

sequenceDiagram participant C as Client participant T as Trident participant B as Backend (Writer) Note over T: 事务中已有写操作
tx_has_writes = true C->>T: Query("COMMIT") Note over T: commit_attempt = true
pipeline_safe_sql("COMMIT") = true T->>B: [write_all]
Query("COMMIT") + Query("SELECT pg_current_wal_lsn()") B->>T: CommandComplete("COMMIT") T->>C: CommandComplete("COMMIT") B->>T: ReadyForQuery(Idle) B->>T: DataRow("16/B374D848") B->>T: CommandComplete("SELECT 1") B->>T: ReadyForQuery(Idle) Note over T: LSN captured, pending_write = false T->>C: ReadyForQuery(Idle)

Pipeline Timeout / 降级路径

sequenceDiagram participant C as Client participant T as Trident participant B as Backend (Writer) C->>T: Query("INSERT INTO t VALUES (1)") T->>B: Query("INSERT...") + Query("SELECT pg_current_wal_lsn()") B->>T: CommandComplete("INSERT 0 1") T->>C: CommandComplete("INSERT 0 1") B->>T: ReadyForQuery(Idle) Note over T: 等待内部 LSN 响应...
internal_query_timeout_ms = 100 Note over T,B: TIMEOUT! 100ms 无响应 Note over T: connection_reusable = false
pending_write = true
discard 后端连接 T->>C: ReadyForQuery(Idle) Note over C: 用户写成功不受影响 Note over T: 下次路由到 Reader 前
Lazy Fetch 补取 LSN

Lazy Fallback 补水位

sequenceDiagram participant C as Client participant T as Trident participant W as Writer Pool participant R as Reader Note over T: pending_write = true
Router 决策 → Reader T->>W: acquire() → 获取 Writer 连接 T->>W: SELECT pg_current_wal_lsn() W->>T: DataRow("16/B374D848") Note over T: record_write(session, lsn)
pending_write = false T->>W: release() → 归还 Writer Note over T: 重新执行 Router.route()
使用刷新后的 session_write_lsn T->>R: Query("SELECT ...")（路由到 Reader） R->>T: RowDescription + DataRow + ... T->>C: 流式转发结果

4.2 Extension 模式

ParameterStatus GUC 上报 — 零额外查询

sequenceDiagram participant C as Client participant T as Trident participant B as Backend (Writer + Extension) C->>T: Query("INSERT INTO t VALUES (1)") T->>B: Query("INSERT INTO t VALUES (1)") B->>T: CommandComplete("INSERT 0 1") T->>C: CommandComplete("INSERT 0 1") B->>T: ParameterStatus("lsn_tracker.last_lsn", "16/B374D848") Note over T: 匹配 extension.guc_name
解析 LSN = 0x16B374D848
record_write(session, lsn)
不转发给客户端 B->>T: ReadyForQuery(Idle) T->>C: ReadyForQuery(Idle) Note over C: 完全无感知
零额外开销

4.3 Aurora Write Forwarding 模式

所有 SQL 发往固定 Reader，Aurora 内核管理一致性

sequenceDiagram participant C as Client participant T as Trident participant R as Aurora Reader (固定) participant W as Aurora Writer Note over T: 首次请求: 选择健康 Reader
aurora_node_id = "reader-1" T->>R: SET apg_write_forward.consistency_mode = 'SESSION' R->>T: CommandComplete("SET") Note over T: aurora_initialized_backend_pid = PID C->>T: Query("INSERT INTO t VALUES (1)") T->>R: Query("INSERT INTO t VALUES (1)") Note over R: Aurora 内核检测到写语句
转发到 Writer R->>W: (内部转发 INSERT) W->>R: (返回结果) R->>T: CommandComplete("INSERT 0 1") T->>C: CommandComplete("INSERT 0 1") R->>T: ReadyForQuery(Idle) T->>C: ReadyForQuery(Idle) C->>T: Query("SELECT * FROM t WHERE id = 1") T->>R: Query("SELECT ...") Note over R: Aurora SESSION 一致性
等待本 session 的写可见后执行 R->>T: RowDescription + DataRow + CommandComplete T->>C: 流式转发 Note over T: 不追踪 LSN
不做读写路由判断
不使用 Router

Aurora 模式动态一致性切换

sequenceDiagram participant C as Client participant T as Trident participant R as Aurora Reader (固定) C->>T: Query("SET trident.consistency = 'global'") Note over T: 拦截并翻译 T->>R: Query("SET apg_write_forward.consistency_mode = 'GLOBAL'") R->>T: CommandComplete("SET") T->>C: CommandComplete("SET") R->>T: ReadyForQuery(Idle) T->>C: ReadyForQuery(Idle) Note over T: session.consistency = Global
后续查询使用 GLOBAL 一致性

4.4 Auto 模式（默认）

Auto 检测逻辑：Pipeline → Extension 自动切换

stateDiagram-v2 [*] --> Pipeline: 会话开始 Pipeline --> Pipeline: 写语句 (无 ParameterStatus) Pipeline --> Extension: 观察到 guc_name
的 ParameterStatus Extension --> Extension: 后续所有写语句
不再追加内部查询 Note right of Pipeline: 初始使用双 Query Frame
获取 commit-time LSN Note right of Extension: 切换后零额外开销
按 session 粒度，不可回退
注意：Auto 模式永远不会自动选择 Aurora Write Forwarding。 原因是 SHOW apg_write_forward.consistency_mode 能返回值不代表 Write Forwarding 真的已启用—— 可靠检测需要查 AWS 控制面 API，SQL 层面无法判定。Aurora 模式必须由运维显式配置。

7. 模式对比

Pipeline Extension Aurora WF
适用后端 任何 PostgreSQL 装了 LSN 上报扩展的 PG Aurora PG (WF 已启用)
额外网络往返 0 (同一 write_all) 0 0 (不追踪 LSN)
额外延迟 ~10-50μs (内部查询执行) 0 0 (代理侧)
写路径 Proxy → Writer 直连 Proxy → Writer 直连 Proxy → Reader → Writer 转发
一致性保证者 Trident (LSN 比对) Trident (LSN 比对) Aurora 存储层
Proxy 复杂度 高 (双 frame + timeout + lazy) 中 (GUC 捕获) 极低 (纯转发)
连接池模式 Transaction / Session Transaction / Session 仅 Session
事务拆分 支持 支持 不支持 (绕过 Router)
降级行为 Timeout → pending_write → Lazy 无扩展 → Auto 退回 Pipeline Reader 不健康 → 报错
SERIALIZABLE 支持 支持 不支持
DDL / COPY 支持 (走 Writer) 支持 (走 Writer) 不支持 (Aurora 限制)

配置示例

# Pipeline (默认，无需额外配置)
lsn_tracking:
  mode: auto
  pipeline:
    internal_query_timeout_ms: 100
    lazy_fallback: true
  extension:
    guc_name: "lsn_tracker.last_lsn"

# ─── 或显式 Extension ───
lsn_tracking:
  mode: extension
  extension:
    guc_name: "lsn_tracker.last_lsn"

# ─── 或 Aurora Write Forwarding ───
lsn_tracking:
  mode: aurora_write_forwarding

pool:
  mode: session          # Aurora WF 强制要求

routing:
  default_consistency: session  # 映射为 Aurora 的 SESSION 一致性
