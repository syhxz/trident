Pool checkout returns a complete BackendConnection. The Handler reads and writes its socket directly, then moves the same object back into the pool; no ConnectionRegistry::take/insert lookup by (node_id, backend_pid) remains. The Transaction-mode idle queue, Session binding, and pinned queue all store complete connections. Session checkout uses move-out/move-back semantics and never clones a connection.

Lifecycle guarantees: a draining pool rejects new checkouts, wakes waiters, and discards connections returned or created after draining begins. Successful cleanup clears the cached application_name; a failed label update prevents the user query from running. Dropping a connection or pool closes every owned socket.

4.4 Auto Mode (Default)

Auto Detection Logic: Pipeline → Extension Automatic Switch

stateDiagram-v2 [*] --> Pipeline: Session starts Pipeline --> Pipeline: Write statement (no ParameterStatus) Pipeline --> Extension: Observed guc_name
ParameterStatus report Extension --> Extension: All subsequent writes
no internal query appended Note right of Pipeline: Initially uses dual Query Frame
to capture commit-time LSN Note right of Extension: After switch: zero overhead
Per-session, irreversible
Note: Auto mode will never automatically select Aurora Write Forwarding. The reason is that SHOW apg_write_forward.consistency_mode returning a value does not prove Write Forwarding is actually enabled — reliable detection requires querying the AWS control plane API. Aurora mode must be explicitly configured by the operator.

Configuration Examples

# Pipeline (default, no extra configuration needed)
lsn_tracking:
  mode: auto
  pipeline:
    internal_query_timeout_ms: 100
    lazy_fallback: true
  extension:
    guc_name: "lsn_tracker.last_lsn"

# --- Explicit Extension ---
lsn_tracking:
  mode: extension
  extension:
    guc_name: "lsn_tracker.last_lsn"

# --- Aurora Write Forwarding ---
lsn_tracking:
  mode: aurora_write_forwarding

pool:
  mode: session          # Required by Aurora WF

routing:
  default_consistency: session  # Maps to Aurora's SESSION consistency
